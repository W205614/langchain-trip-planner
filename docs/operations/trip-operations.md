# 行程执行工作台

Java 继续持有行程、账号、权限、审计和数据库事务。新增的执行工作台通过 `V6`、`V7`、`V8` Flyway 迁移保存行前核验、预订事项、实际费用、同行成员、站内通知和用量提醒。Python Agent 的生成、路线和 RAG 职责不变。

## 行前核验与局部改排

- 所有者调用 `POST /api/trips/{id}/checks?day_index=N`，带当前 `If-Match`。Java 读取该版本的日期和 POI，仅以高德 REST 对选定日期做营业信息和天气预报核验；单次最多 60 个景点，地图调用预算约 30 秒，超时未查的景点记为待确认。核验只写 `trip_checks` 与 `trip_risks`，不修改行程或假定地图营业时间适用于出行当日。
- `GET /api/trips/{id}/checks/latest?day_index=N` 返回最新核验及其 `stale` 标志。行程版本变化或 6 小时后结果过期。地图暂不可用、目标日期没有预报、营业信息缺失都明确记录为待核验；地图营业信息变化和恶劣天气只是提醒，最终仍以目的地官方来源为准。
- 编辑者可标记风险“已知悉”，该动作不能清除风险或证明地点已开放。所有者可从工作台打开原行程，使用既有的 `revise-task` 对目标日期发起局部改排。风险本身不会自动触发模型调用。
- 临行提醒在 `TRIP_REMINDER_ZONE`（默认 `Asia/Shanghai`）的出发前一天生成一次站内通知。它只提醒查看，不代替核验。定时任务默认每小时扫描一次，`trip_records(start_date,id)` 有索引。

## 预订与实际费用

- `trip_commitments` 记录用户输入的待确认、已确认、已取消事项及可空金额；`trip_expenses` 记录实际支出。两者是用户账本，不表示系统已完成预订、支付或确认实时价格。
- 新建预订事项和支出要求 `Idempotency-Key`。同键同内容返回原记录；同键不同内容返回 409。更新预订事项使用自身的 `If-Match` 版本；支出不覆盖，错误记录需要说明原因后撤销，审计痕迹仍保留。
- 费用概览分开展示原计划估算、已确认预订金额、实际支出和金额未知的事项；均以整数分存储。确认但金额未知的事项不算作 0 元。仅行程所有者或已接受邀请的编辑者可写。

## 同行成员

- 所有者按已注册用户名邀请，权限为 `viewer` 或 `editor`；受邀人必须在 `/inbox` 接受后才能读取工作台。变更成员角色会重新置为待接受，原权限立即失效；重复邀请同一角色不会产生新通知。用户可拒绝邀请或退出，所有者可移除成员，移除后再次邀请会生成新通知。
- 编辑者目前可修改当天主题说明，并对某一天**已有的可信 POI** 调整顺序。接口验证 POI 集合、当前行程版本和成员权限；保存后重新计算本地约束并提示路线仍需核验。它不允许凭共享身份新增地点，也不授予资料、任务、账户或管理员权限。
- 成员编辑事务在成员行上持有共享锁，避免成员被撤销后仍提交中的权限竞态；版本捕获归属原所有者，审计动作记录实际编辑者。

## 站内通知与成本提醒

- 邀请、风险、同行变更、临行提醒和 Token 阈值事件写入 `trip_notifications`，以用户及事件键去重。通知在站内读取和标记已读；没有外部邮件或短信发送。
- `/api/usage/summary` 汇总本月已持久化任务报告的模型调用、输入和输出 Token。用户可设置每月 Token **提醒阈值**，到阈值后站内通知，不会自动拒绝任务。取消后上游迟到的用量或供应商未报告的用量可能缺失。
- 只有明确配置 `TRIP_INPUT_PRICE_PER_MILLION_USD` 和 `TRIP_OUTPUT_PRICE_PER_MILLION_USD` 时才显示美元估算；默认不估价。单价由运维按实际供应商和模型维护，不在代码中硬编码。

## 验收边界

隔离 PostgreSQL 集成测试覆盖核验不改写原计划、权限和接受邀请、版本冲突、成员编辑审计、费用幂等与撤销、通知去重及 HTTP 鉴权。前端用 `npm run build` 校验。真实高德/模型调用、第三方预订、外部消息投递和生产容量需要独立验收；本地固定样本不能证明这些能力。
