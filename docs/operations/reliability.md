# 单机上线故障处理与恢复

适用：单个 API 进程、单机 PostgreSQL/SQLite、派生 Chroma 索引。本说明不承诺高可用或自动恢复进行中的模型调用。

## 结果契约

`success` 表示请求处理与结果交付成功；规划是否完成以 `quality.outcome` 为准：

| 状态 | 处理 |
| --- | --- |
| complete | 满足当前完成门禁；预约、入园、内部步行等未接入事实仍单独声明 |
| degraded | 完成门禁通过，但使用规则安排、天气或攻略增强缺失 |
| draft | 保存可信的已有内容，但存在空白日期、必去缺失、约束违规或路线不足以核验限制 |
| failed/cancelled | 没有可交付结果或明确取消；不保存迟到结果 |

草稿对应任务终态 `needs_attention`。普通接口、SSE complete 事件、任务详情都会携带质量信息。SSE 的 complete 表示本次处理结束，不代表行程要求全部满足。旧客户端须先升级，再启用新后端。

草稿不进入历史向量检索。将已有行程改成草稿时，事务内写入删除同步任务；查询端立即检查主记录的草稿状态，删除异步完成前也不返回旧向量。重建同样排除草稿。

单日改排若产生草稿，另存历史记录并记录 `revision_parent`，原行程保持原样。确认应用使用草稿的 `If-Match` 及原行程版本双重检查；确认只代表用户接受修改，不会把未满足要求改成已通过。

## 草稿与降级

| 现象 | 定位与处理 | 用户下一步 |
| --- | --- | --- |
| 无真实 POI | 查看 `TRUSTED_POI_UNAVAILABLE`、地图依赖与候选过滤日志；不生成占位景点 | 稍后重试或更换目的地 |
| 未满足必去/日期空缺 | 查看 `quality.issues`，检查名称歧义、跨日重复和候选数量 | 补全名称、减少天数或调整要求 |
| 路线缺失 | 不把未知时长当零；检查地图服务和交通模式 | 稍后重试，或减少景点 |
| RAG 片段错配 | `trip_rag_events_total{reason="entity_rejected"}`；核对标题、实体绑定和来源 | 不回填该片段，仍可查看基础行程 |
| RAG 超时/拥堵 | 查看 timeout、busy、lock_timeout；检查嵌入供应商及索引任务 | 基础规划继续，研究接口显示暂不可用 |
| 天气/图片/报价缺失 | 显示未知或占位，不创建天气、价格事实 | 出行前查询官方信息 |
| 保存失败 | 先用原 task_id 查询状态，再沿用幂等键提交；不得直接宣称成功 | 保留页面中的任务信息 |
| 页面断网 | 后台任务独立运行；刷新或到“我的任务”读取 | 不需要重复创建任务 |

RAG 采用两个并发槽；单次增强总预算 8 秒，单次嵌入请求最多 3 秒，索引锁等待最多 0.2 秒，槽等待最多 0.1 秒，均受任务剩余时间约束。嵌入 HTTP 使用可取消的总超时，持续发送小片段也不能无限延长请求。网络工作在索引锁外完成，提交前检查索引代际；代际变化则拒绝本次写入，由同步任务重试。索引重建若发现并发写入则保留旧代。

格式或身份不匹配不做自动重试。LLM 解析修复保持原有有限次数；网络错误不叠加 SDK 无限重试。图文永久解析错误及明确 400/401/403/422 不重复调用视觉模型，待修正资料或配置后重新解析。

## 图文复核

1. 初审批准只进入解析队列。没有可提取事实的页面失败，不把标题/页码当知识发布。
2. `awaiting_review`：管理员通过受鉴权保护的原件和分页文本对照复核。标题三级层级用于景点实体归属；城市参考不能绑定给某个景点。
3. 表格跨页、否定条件、同名景点及资料内的指令必须人工核对。解析不是事实认证，来源标为官方也不跳过复核。
4. 保存修订会增加版本；发布必须提交当前版本，旧版确认返回 409。发布过程仍检查状态和版本，拒绝/删除后不能重新公开。
5. 草稿文本保存在 `extracted_pages_json`，公开后另存 `source_text`；重建优先使用已保存的分页内容。旧版已发布资料保留，界面标明没有新复核记录。

超长段落不截成半句话；不完整表格不拼接成确定事实。实体无法唯一解析时舍弃增强。本轮没有引入未经标定的相似度阈值。

## 同步与资源

监控草稿数/率、模型降级原因、RAG 拒绝/超时、任务队列年龄、同步任务年龄、worker 存活和数据卷剩余空间。已有 Prometheus process 指标在支持的平台提供进程资源信息；磁盘低于 10% 持续 2 分钟告警。进程存活不等于 worker 正常，worker 存在也不等于处理有进展，须同时看积压年龄。

索引同步积压超过 10 分钟：先核对数据库、嵌入凭据、磁盘空间与 worker，再使用现有管理员重放入口。不要循环重放永久解析失败资料，不要删除主数据库来“修复”索引。

磁盘不足：暂停新增资料，检查日志与备份保留；在完成备份校验前不要清理主库和上传原件。索引可重建，原件与数据库不可互相替代。

告警规则见 `deploy/alerts.yml`；本地通知演练验证的是 Prometheus → Alertmanager → 本地接收器，不代表外部值班渠道已经配置。

## 发布与恢复

- 本轮迁移 `b3c4d5e6f7a8` 仅新增提取分页列；旧历史质量不重写。通过 API 返回时缺少新门禁标记的记录显示未评估。
- 维护窗口停止写入后，备份 PostgreSQL 和上传原件，保存校验和；环境配置与凭据另行加密保管，不进入 Git 或报告。使用已有 `backend/scripts/backup_local_deployment.py` 前核对实际部署目录。
- 先发布支持草稿状态和复核流程的前端/API，再迁移并发布新后端。此仓库支持同一发布窗口更新前后端，不支持旧客户端长期读取新终态。
- 先在隔离数据库验证迁移及回退；生产回滚优先回退应用并保留新增列，避免删除尚未复核的内容。若必须降级 schema，先导出分页提取资料。
- 恢复数据库与原件到新目标，校验各表行摘要与文件校验和，再从主数据重建索引；验证草稿不入库、公开资料版本和用户隔离后，才切换服务。
- 隔离环境命令：`docker compose -p trip-validation -f docker-compose.validation.yml up -d --build`。该栈使用独立镜像与数据卷，不挂载日常数据，也不读取日常 `.env`。
- 恢复演练：`python backend/scripts/recovery_drill.py --output docs/evidence/hardening-20260913/recovery.json`。通知演练：`python backend/scripts/notification_smoke.py --output docs/evidence/hardening-20260913/notifications.json`。演练会暂停隔离栈后端，不暂停日常服务。

分块方式已改变，历史检索基线的 chunk ID 不能直接当作新索引金标准；需要重新标注/映射后才能比较检索指标。本轮故障测试通过不等于语义检索准确率通过。
