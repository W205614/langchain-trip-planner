# 时间规划、受限改排与恢复运维

本项目部署边界为单机四服务。PostgreSQL 是业务事实源，Chroma 是可重建的派生索引；无多机高可用承诺，无查票／支付集成。下列配置是源码默认值，实际部署以有效环境及镜像版本为准。

## 输入、方案与权限

旧请求保持可用，结构化能力通过 `planning_input` 增量加入。行程方案版本与规划输入修订号独立推进：前者表示已生效方案，后者绑定约束、锁定、完成和相关预订输入。所有者编辑约束需同时提交 `If-Match` 和规划输入修订号；相关预订变动也会推进修订号。

所有者管理约束、锁定、完成及 AI 提案；编辑者继续使用原有手工调整与费用账本；查看者只读。待接受、已撤销和无关用户没有私有行程读取权限，管理员的资料治理身份也不赋予私有行程所有者权限。服务端逐次检查，浏览器缓存不作为授权依据。

预约 `fixed` 表示整个占用时段固定；`entry_window` 表示允许开始入场的窗口，游览时长另填 `duration_minutes`，离场可以晚于入场窗口结束。跨城交通必须由用户确认班次、完整日期时间、起终位置及费用身份。班次起止不等于已核实进站、安检和检票提前量：当前模型尚未确认这一要求，时间轴会保留提示，不能据接驳恰好到站认定一定赶得上。应向承运方核实并在输入中预留到站时间。没有可靠的预约／营业数据时保留未知，不推断旧数据中不存在的事实。

时间求解先处理硬约束，再比较需求满足、改动量、交通等待和偏好。默认每日最多 20 个活动、路线查询最多 120 次、单日求解 2 秒、整次求解 30 秒；分别通过 `PLANNER_MAX_DAILY_ACTIVITIES`、`PLANNER_ROUTE_LOOKUPS`、`PLANNER_DAY_SECONDS`、`PLANNER_TOTAL_SECONDS` 配置。最多两轮相邻日期改善。普通 AI 餐厅是可选候选，排不进去时保留明确餐饮缺口；显式用餐窗口、确认预约、锁定和完成活动仍是硬约束。未确认的推荐住宿会结合次日固定交通，在已有可信候选中有界筛选并核验接驳；固定住宿或范围外住宿保留冲突，展示更早出发／换住宿的显式选择，不自动放宽时间。到达上限不静默删除必去活动，也不把未找到误报成已证明无解。

## 事实与提案

事实保留实体、城市、来源、获取时间、适用日期和确认状态。营业／票价默认 24 小时，路线 30 分钟，天气 1 小时，核验报告最多 6 小时；来源更短有效期优先。用户知悉风险不会改变事实确认状态。核验只输出受影响活动与改排入口。

改排提案绑定原方案版本、输入修订号、相关预约及事实依赖；确认保存的是已预览内容，不再次调用模型。日期／时段／活动范围外业务内容、用户锁定及已完成安排由 Java 再次保护。范围扩大需用户明确选择。修改手工安排后，相关日期时间轴会标记过时，不能据此新建时段锁或完成记录。

## 执行与付费预算

Java 持久化任务、当前执行、期限、阶段快照和调用预留。Python 通过内部鉴权 v2 接口读写；协议不一致直接失败。阶段写回必须属于当前仍有效执行；取消、超时和旧执行不能复活。

恢复接口 `POST /api/tasks/{id}/resume`（兼容 `/api/trip/tasks/{id}/resume`）要求幂等键，保留原终态任务并新建关联执行。只有输入哈希、模型／规则／提示版本及事实有效性兼容的阶段会复用。恢复求解复用仍有效的候选、草稿和有向路线；旧失败路线保留未核实占位，不自动再次发送。规则升级仅对明确兼容且未受影响的阶段开放复用，排程阶段必须重新计算。成功落库后的索引仍可能产生独立 Embedding 调用，不能将求解零调用解释为整个异步链路免费。无法确认是否收到外部响应时不承诺费用恰好一次。

Java 高德请求（含照片）及 Python 模型／Embedding／地图调用均先向 Java 预留，SDK 重试也受覆盖。`OUTBOUND_LEDGER_REQUIRED=true` 用于部署；账本不可用时停止付费调用。日常文本／嵌入／地图默认上限为1000／5000／10000，可在 Java 运行环境分别设置 `OUTBOUND_DAILY_TEXT_LIMIT`、`OUTBOUND_DAILY_EMBEDDING_LIMIT`、`OUTBOUND_DAILY_AMAP_LIMIT`（UTC自然日）。任务及其恢复后代共享祖先任务额度，上限还随天数有界增长。单次真实验收使用固定 `FINAL_ACCEPTANCE_RUN_ID`，服务端上限固定12／40／400，独立于日常额度；失败发送不退回。禁止换编号绕开验收上限，禁止清理运行账本。

`outbound_budget_counters` 可按 scope、kind 查看已预留计数；`outbound_reservations` 中 unknown 表示已预留但不确认响应是否落库。查询时只输出汇总，不公开凭据、任务正文或私有账号。

## 索引及调度故障

行程和索引 Outbox 同事务提交，网络调用在事务外。索引失败可以重放，版本水位与删除墓碑阻止旧作业复活记录；重建和差异检查沿用[迁移手册](java-migration.md)。不要为修复检索删除业务库。单实例锁连接失效后，调度停止领取任务且 readiness 失败，重新取得所有权前不恢复领取。

先看任务状态、错误分类、request_id 与执行 ID，再看 Agent 和数据库；资料无匹配与检索服务故障分开处理。禁止仅凭健康检查将业务验收标记通过。

## 备份、迁移与回退

先记录 `docker inspect` 的实际挂载和 Compose 覆盖文件。默认部署可能是绑定目录，不能假设使用命名卷。停写后停止 backend／agent，保持 PostgreSQL 可读，执行：

```powershell
python backend/scripts/backup_java_deployment.py --output backups/release-YYYYMMDD-HHMM --archive-images
```

脚本拒绝覆盖旧目录，备份数据库、上传、Chroma、运行账本、有效私有环境和旧镜像，并写哈希清单。私有备份不能提交。完成后重新启动原服务，或进入已经批准的升级窗口。

恢复只写入新的外部目录及隔离 PostgreSQL，验证哈希、原表内容和旧后端 readiness。候选升级会另外核对原业务列和已发布迁移记录：

```powershell
python backend/scripts/restore_java_backup.py --backup backups/release-YYYYMMDD-HHMM --output E:/recovery/trip-check-YYYYMMDD --candidate-image candidate-backend:tag
```

Docker 默认地址池耗尽时可加 `--network-subnet` 指定经检查未占用的 CIDR；脚本拒绝与已有 Docker 网络重叠。恢复副本保留供检查，报告列出精确容器／网络，检查后按名单清理；不删除原卷或归档。

先在恢复副本验证 Flyway 新增迁移，再使用已验收候选镜像更新日常四服务，保持原挂载。升级失败且数据不兼容时，按已验证的备份恢复步骤回退，不能只切旧镜像。新容器还需历史兼容和规划／确认链路验收。清理限于本次验证容器、网络及已归档、无引用的明确项目镜像 ID；禁止全局 prune、`down -v` 或删除 `.env`、账本、备份。
