## 发现并修复

1. 手机首页的顶部入口会被挤出屏幕；改为窄屏换行布局。[手机截图](mobile-home.jpg)。
2. 行程结果页在约 737px 宽度出现横向溢出，地图超出视口；调整信息区、地图和侧栏的响应式布局。修复后该宽度 `scrollWidth=730 <= innerWidth=737`。[修复后截图](desktop-result-after.jpg)。
3. 重新构建前端后，旧标签页加载已删除的懒加载 JS 文件会停留在原页面；路由对这类加载失败只重载目标页一次，保留查询参数。Nginx 对 HTML 禁用缓存、对不存在的旧资源返回 404，对指纹资源启用长期缓存；部署回归覆盖此路径。
4. 历史、社区、审核、通知把 UTC ISO 文本直接显示给用户；统一按浏览器本地时区格式化。
5. 探索页一次渲染 90 张地点卡片，滚动和首屏体验差；改为每页 12 张并允许翻页。重建后的浏览器实测 12 张、存在分页控件，页面没有横向溢出。[探索截图](explore-paginated.jpg)。
6. 慢任务达到截止时间附近，网络流关闭有时被记录为 `AGENT_CONNECTION_LOST`；现在以任务截止时间区分 `TASK_TIMEOUT`。提前断开 Agent 仍报告 `AGENT_CONNECTION_LOST`。
7. 增加 16 个同时确认/放弃同一提案的数据库集成测试：只有一个请求成功，其余 15 个版本冲突；原行程版本只在确认时增加一次，索引 Outbox 也只写入一次。

## 并发与故障注入

单机、离线替身、同一只读历史接口的 1/8/32/64/128/256 并发短时阶梯均无 HTTP 错误。256 并发持续 30 秒得到 13,045 次请求、428.2 QPS、P50 0.456 秒、P95 1.460 秒、P99 2.178 秒、0 个非 200 响应；[阶梯及任务](performance-after.json)、[持续读压](read-soak-256.json)。

24 个并发慢规划提交中，12 个返回 `202`，12 个由 Java 持久任务队列以 `429 TASK_QUEUE_FULL` 拒绝。被接受任务最终 4 成功、8 个因 30 秒测试截止时间失败；45 秒内没有悬挂任务。期间健康检查及历史接口仍响应，未观察到重复写入或跨用户数据混淆。这表明当前配置在写任务拥塞时采用有界拒绝，不能据此声称可承载 24 个同时运行的真实模型规划。

Agent 被停止时 16/16 请求返回 `503 AGENT_UNAVAILABLE`，Java 健康接口保持 200；地图替身被停止后先返回 `AMAP_BUSY`/`MAP_UNAVAILABLE`，随后断路器返回 `AMAP_CIRCUIT_OPEN`，恢复后请求 200。告警触发和恢复通知均送达本地接收器。并发确认/放弃由数据库事务测试校验一次性收口。

## 尚不能下结论的部分

- 尚无真实模型、高德地图调用的受控并发样本；以上 QPS 与任务耗时只描述本机离线替身。
- 合成约束和人工浏览不能证明真实旅游信息准确、真实用户满意度或所有浏览器与屏幕尺寸。离线改排样本本身是 `degraded`，餐饮、开放时间、预约和部分路线仍需外部核实。
- 任务队列在此配置下先达到容量限制；生产容量需要按真实模型响应时间、地图配额、机器规格和目标延迟另行制定并测试。
