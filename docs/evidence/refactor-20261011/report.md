# 2026-10-11 可读性整理与容器验收

本轮基于 `5baebadafe64d9a38697d76a4c2918eb8eddb5da` 的工作树，小步清理有证据的冗余，不改变公开 API、内部 JSON 协议、数据库迁移、Java 业务规则或 Vue 页面结构。发现的是局部冗余，不能把测试数量多直接判断为过度测试。

## 修改依据

- Agent 的旧整程 JSON 解析、旧整程 prompt 构建及 Agent 信息方法没有调用点，删除后仍保留实际逐日生成、解析、天气与 POI 文本辅助方法。
- 通用异常处理器未在实际 Agent 应用注册，仅用于构造测试应用；删除该处理器及其模拟 500 测试，保留实际使用的业务异常响应与默认 404 检查。
- 旧离线场景清单只被名称检查测试读取，没有执行行为；删除这两份文件。
- RAG 维度探测超时有两处重叠测试；合并为参数化用例，保留正常状态、已有降级状态、向量不丢失及恢复查询返回原文的断言。
- RAG 共享夹具移到普通辅助模块，由 `conftest.py` 注册，消除测试文件之间的导入依赖。
- 保留逐项冻结场景和独立 benchmark 报告，删除再次运行同一整套场景的汇总测试及必须超过历史基线的断言。

事务、幂等竞争、版本冲突、所有权隔离、取消、恢复和 Java／Python 协议检查验证不同边界，继续保留。跨语言的生成端规则与校验端规则也未合并。

## 真实链路与数据保护

在日常生产配置及原本机数据覆盖文件上，使用独立验收账号完成一次北京单日生成和一次单日改排。生成已保存、必去故宫满足、不去八达岭满足；改排确认前原行程不变，确认后版本增加一次，重复确认返回 409。浏览器实测登录、持久化行程及事实缺口提示；该页面检查阻止额外图片和地图资源请求。

生成及改排均为 `degraded`，仍存在餐饮候选、酒店／餐厅接驳、景区内部步行、出行日开放时间及预约核验缺口。本次两个有限真实样本不证明所有城市或全部旅行事实准确。

验收 Agent 使用独立持久化账本，记录文本 2、嵌入 8、高德 73 次调用，均在已有上限内；旧账本未重置，失败预留不退回。验收完成后恢复日常配置，账本文件留在本机。该账本统计 Agent 调用，不是整个平台的费用核算。

业务与 Agent 停止期间完成数据库、上传、Chroma、Agent 运行数据及私有配置备份；8 个清单文件哈希、文件归档读取及数据库归档目录校验通过。实际恢复到独立数据库后启动旧后端，23 张表、519 行的全部表哈希与原库一致。重建日常容器后、真实验收新增数据前，同样核对 23 张表、519 行完全一致。
