# 2026-09-29 真实服务链路验收

## 范围与环境

从 `http://127.0.0.1:8380` 经 Nginx、Java、Python Agent 请求真实文本模型和高德 MCP；使用 `docker-compose.production.yml` 与独立的 PostgreSQL、Chroma、上传和 Agent runtime 数据卷。没有开启 fixture 路由，也没有使用测试账号已有行程。私有凭据、令牌和调用账本留在仓库外或忽略目录，不进入本报告。

本轮只验证了有限的单日样本，无法据此保证真实旅行事实或所有功能都正确，也不能推断真实模型的高并发容量。`/api/capabilities` 的 available 代表配置可用，不代表每次上游调用成功。

原始生成的资料检索曾因超时降级为关键词，结果页明确显示资料缺口。首次界面检查还发现旧提案重复显示和 11:00 开门的餐厅被标成早餐；修复后分别复查了历史列表与新生成样本。新样本的高德受控额度最终达到 100 次预发送上限，因此路线数据不完整。这是本轮测试额度的停止结果，不代表高德在正常配置下不可用。

## 运行与复核

本轮完成后，移除私有 `deploy/runtime/agent.env` 中的 `ACCEPTANCE_BUDGET_FILE` 配置并重建 Agent，保留原账本作审计；运行中的应用不受已用完测试额度阻断。四个长期容器是 `frontend`、`backend`、`agent` 和 `postgres`，仅前端在宿主机 `127.0.0.1:8380` 发布端口。验收时额外使用的 PostgreSQL 测试容器和 Python 一次性测试容器已停止或自动移除。

后续需要单独验证多日、多用户、资料上传审核、社区发布、实际出行日期营业时间，以及真实模型并发的超时和成本；先设额度与停止阈值，再记录请求样本和失败。历史离线压测只覆盖读接口与替身任务，不能换算成真实模型吞吐。
