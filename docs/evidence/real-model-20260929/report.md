# 2026-09-29 真实模型与地图低频抽样

## 执行边界

保留运行中的 `trip-validation` Docker 栈及其数据库、前端和离线 Agent。使用相同的 Agent 镜像启动两次一次性进程，读取主工作区现有的私有模型配置，分别调用真实 `deepseek-v4-flash` 模型和高德 MCP。没有把密钥复制进仓库、报告或长期运行的验证容器。评测输出不包含原始模型回复、密钥或付费接口 URL。

本测试**直接调用 Python Agent**，没有经过 Java HTTP/SSE、鉴权、任务持久化、原行程版本校验或浏览器。RAG 显式禁用，避免把未准备的知识库误算成真实检索效果。现有 [前端](http://127.0.0.1:18080) 仍连接离线替身；其页面生成结果不能当作本报告的真实模型结果。

两次调用共用一个持久的预发送计数账本。上限为模型请求 3 次、高德 MCP 工具调用 80 次；实际预留为模型 2 次、高德 74 次。预留计数包含失败的发送尝试，不等于上游成功计费次数；供应商真实费用没有在本地配置，因此报告中的估算金额 `0` **不代表免费**。两次测试的模型用量由供应商返回的 token 元数据记录。

## 发现与后续判断

- 地图工具的预发送计数在第一份样本达到当时的 30 次上限；第二份再增加 44 次，合计 74 次。常规单日请求会消耗数十次地图工具调用，是配额和延迟风险。第一份即使通过确定性规则，部分可选地图事实仍可能因 30 次上限降级；本次未把它判定为完整地图质量通过。
- 第一份返回的输出 token 为 2,064，高于当前单日请求参数 `max_tokens=1800`。不同供应商对返回用量的统计可能包括额外 token；这里只记录观测值，不能据此断定服务端违反上限，但容量估算不宜直接按 1,800 token 计算。
- 样本量仅为 2，均为北京单日；不能推断真实模型的并发容量、P95、失败率或真实用户满意度。当前持续运行的验证栈仍为离线模式，之前的 256 并发结果也仍只适用于离线替身。

复现第二份样本的入口为 [`backend/scripts/live_model_sample.py`](../../../backend/scripts/live_model_sample.py)。继续调用前应检查持久账本 [`call-budget.sqlite3`](call-budget.sqlite3) 的剩余额度；脚本使用预发送计数阻止超过指定上限的调用。
