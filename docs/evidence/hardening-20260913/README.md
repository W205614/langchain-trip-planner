## 完成的行为变化

- 完成门禁统一输出 `complete / degraded / draft` 与结构化问题。规则不满足时任务为 `needs_attention`，保存草稿但不宣称规划完成；没有可信景点仍失败。
- 草稿在任务、历史、结果页与导出中保留状态。改排草稿另存，原行程不被覆盖，确认应用验证原记录和草稿两个版本。
- 创建草稿不写历史向量；既有记录变为草稿时异步删除向量，检索可见性过滤立即生效；索引重建排除草稿。
- 景点来源统一校验身份、类别、坐标及上游明确报告的城市。知识库按名称补充时用唯一解析，拒绝售票处和歧义匹配。
- 景点详情按实体归属校验，POI ID 优先、唯一别名其次；同城不等于同景点。保留标题路径和完整段落，超长或归属不明的内容不强行拼入。
- 图文解析结果进入待复核，空事实不能发布；原件与分页文本仅管理员可读取。修订增加版本，发布绑定当前版本。
- 嵌入远程调用移出索引锁，限制并发与总时间；持续缓慢回包也会取消。索引提交检查代际，重建期间有写入则保留旧索引。
- 研究功能区分无匹配与服务不可用，前端错误后清除旧证据。新增草稿、RAG 拒绝、同步停滞和磁盘空间告警。
- 上传写入失败回滚记录；文件使用唯一名称，提交状态不明时保留文件，只有数据库确认不存在时才清理。

## 真实样本的判断

本次真实任务返回两个 POI：故宫博物院-交泰殿、北京古代建筑博物馆；路线查询成功，超时长修复移除了一个候选，当前确定性检查通过。攻略详情未全部可靠匹配，结果为 `degraded`，没有把错误片段强行回填。

这同时暴露了数据边界：景区内部建筑虽有真实 POI ID，仍不等于独立可入园、可购票的景点。当前未接入景区包含关系、预约余量和旅行日期的精确开放校验，不能把规则通过解释为现场可执行性的完整证明。

真实样本只证明一次链路可完成；没有做长时间压力测试、供应商故障率统计或盲测检索评估。嵌入连通测试不证明语义检索准确率。未配置的供应商单价没有被猜测为费用指标。

### 部署后修复：研究入口误报配置缺失

北京查询反馈暴露了部署健康检查未覆盖的启动状态问题：嵌入配置存在，但启动维度探测失败会把 RAG 持续标记为不可用。修正后，超时或传输故障不会锁定禁用状态，后续请求可恢复；已确认的维度不匹配和模型变更仍阻止检索，Chroma 的逐次向量维度检查保留。禁用提示不再把所有原因归为缺少配置。

隔离容器中 15 项 RAG 测试通过（包含新增的两种探测超时状态用例）；首次单文件运行缺少数据库表，初始化隔离数据库后复验通过。后端镜像再次构建并替换，健康检查通过。实际北京“故宫参观注意事项”查询在后端接口及前端代理均返回 HTTP 200、matched、5 条证据，来源包括 beijing.md 和高德北京资料。该结果证明查询链路恢复，不代表全部片段的语义正确性。

前述 checks.json 和 daily-deployment.json 为这次后续修复之前的验收快照；新增修复未重跑整套验收，以上为对应的增量验证记录。
