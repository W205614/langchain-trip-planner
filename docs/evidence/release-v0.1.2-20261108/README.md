# v0.1.2 本地规划质量修复与验收

本轮处理独立景点候选、明确数量目标、到离时间窗口、餐饮和路线衔接，以及告警接收进程正常退出。继续采用单机部署，不增加依赖、数据库迁移、云服务或 Packages。最后完整真实模型恢复抽样源为 `fe9807b38695d2a102dbc4437ca6888866cf5fc7`；后续数字边界、到期修复与供应商路线复测对应业务源 `1e555625670da110c91c8c92b8438f531e070086`。正式 Tag 的最终提交及完整 CI 状态以 [Release](https://github.com/W205614/langchain-trip-planner/releases/tag/v0.1.2) 发布凭据为准。

## 已修复

- 以独立候选数量决定是否有限补搜；疑似父景区与内部点不占用两个备选名额，必去、预约和用户确认的独立关系继续保留。短日优先紧凑候选，距离排序不等于真实路线核验。
- 名称按完整数字边界匹配，避免把“景点1”和“景点10”误判为父子。原90个合成候选曾被合为10组、导致30天场景20个空日；修复后90组、无空日，原夹具完整生成30天/90个唯一POI。未修改夹具或降低数量断言。
- 每日明确数量、可用时段和可排餐次进入实际模型提示；初始数量未满足单独提示。修订不重新套用旧的全程目标，历史内容不自动重写。
- 餐饮缺口在排程后按有效日窗重算，显式餐窗仍是硬约束。已有真实夹具现在两天午餐均可排入；断言精确核对剩余早餐、晚餐，而非沿用旧缺餐总数。
- 路线先查必要接驳，最终只汇总选中路线的状态和原始期限；未选中的失败边不会使整天失效。必用跨城接驳若在求解期间过期，同步降级，不续期、不自动重发。
- 未知端点没有供应商事实，不再伪造 EPOCH 到期事实；仍明确未核验。真正失败、未观测、已过期的供应商事实保留原无效期限及确认校验，修复未知端点导致正常提案被误拒的问题。
- 缺少实际到达／离开地点时保留明确提示和估算，不用推荐酒店代替车站。无住宿及离开安排的最后一天不额外添加返回住宿；中间日期仍保留住宿需求。
- 已选路线因预算尚未发送时保留待恢复状态；修复普通完成状态导致恢复接口拒绝的问题。先合并检索提示再保存草稿，修复恢复时路线哈希因提示不同而变化。
- 告警接收进程响应 SIGTERM，完成当前原子写入后关闭服务。隔离 PID1 对照中，旧版退出码137，修复后约0.85秒退出码0，收件内容保持完整。

## 真实 API 验证

使用真实 OpenAI 文本模型和高德 MCP，日常数据库未用于本轮样本；RAG、视觉和新 Embedding 调用未纳入本轮验证。完整计数汇总见 [validation-summary.json](validation-summary.json)。

|---|---|
| 西安两天，首日13点到、次日16点离开、每天两个景点 | 最终普通 v2 接口样本保留 `[2,2]` 个独立景点；日期、到离边界、无 fallback、唯一 POI 和未核验提示均通过。未知到离地点继续提示 |

| 杭州 v2 默认配置及恢复 | 默认30秒／120次路线查询、Java300秒。测试在一条真实地图响应后人为延迟31秒，首轮 `needs_attention`，实际恢复接口返回的子任务 `succeeded`；12项检查通过。首轮1次新模型调用，恢复无新增模型调用；原路线哈希、观察时间和期限不变，延后路线实际查询，最终保留2个景点 |

累计6次生成（西安4次、杭州2次），其中初测暴露的问题已按复现修复，不能将初测均记为通过。另做上述路线复测；全轮新增文本调用计数10、高德工具计数501，保留同一账本，累计文本60、地图1588、Embedding23、视觉1。数字边界修复还重放15组历史真实POI关系，原父子与独立关系均保留。计数不代表供应商实际账单或普遍准确率。31秒延迟为人工注入，不能描述成真实供应商故障。

Windows 测试脚本曾用 GBK 解码 PostgreSQL 的 UTF-8 JSON。修正解码后继续同一个未完成任务验收，没有重新生成、重置计数或抹除失败记录。

## 自动化验证

- Python 全量 `pytest -q -rs`：696通过、10项环境跳过；其中9项原生 ABI／回补检查在候选运行镜像中另行通过，剩余1项为本地未配置固定版本 restic。正式 CI 中另核对相应环境结果。
- 前端 `npm run build` 通过；构建产物上的结果页浏览器测试13项通过，覆盖目标提示去重及端点说明。这组浏览器测试使用隔离响应，不作为真实模型测试。
- 新行为先在旧实现上失败，再在修复后回归。默认恢复还覆盖选中延后路线、未发送与已发送失败区分，以及实际 v2 生命周期中检索提示、草稿和路线快照一致性。
- 实际五服务离线供应商联调通过：Nginx上传边界、22个业务样本、助手提案确认、42项角色和66项规划场景。基于Nginx构建产物的13项结果页浏览器回归通过；这些不作为真实供应商或生产容量证据。
- 安全工作流使用正式四语言 CodeQL 产物及源码绑定复核。中间版本的 PostgreSQL 扫描、OSV 下载曾读超时，记录为无法完成，未作为漏洞扫描通过；最终版本必须通过实际门禁后才正式发布。

四语言原始26项结果与此前版本完整比对无新增或变化，[本轮 CodeQL 复核](../schedule-fix-20261108/codeql/1e55562/README.md)包含88项业务绑定；两份工具源码另行按SHA与AST复核，不伪称属于现有策略自动绑定范围。`main.py` 的一行移动也触发了原 Chroma VEX 绑定拒绝；重新读取入口和授权边界、执行3项无网络嵌入式测试后更新唯一受影响绑定，见[具体依据](embedded-chroma-review.json)。四组既有 CVE 评估及依赖版本保持不变，不将此描述为修复上游库。

固定版本扫描器的下载曾连续读取超时，增加最多3次、仅限超时的下载重试；完整SHA验证通过后才缓存，错误内容和最终失败仍拒绝，实际扫描判定未改。5项下载边界及81项工具测试通过，见[具体复核](scanner-download-review.json)。本地首次干净镜像构建也遇到pip下载中断，保留失败日志后重新构建完成，未修改依赖来绕过问题。

## 升级与限制

保留已有私有配置和持久挂载，更新 Agent、前端及告警接收镜像；其余组件没有本轮代码变化。数据库仍为 Flyway V20，无新增迁移。已有安装不重新运行首次配置生成脚本。操作与快照兼容边界见[规划与恢复手册](../../operations/final-planning.md)及[七服务运行手册](../../operations/single-host.md#现有七服务部署操作)。

数量目标仍受真实候选与时间约束，不保证任何输入都能排满。天气时效、营业、预约、票价、酒店和未知地点仍需核实；真实结果保持 `degraded`，不冒充事实齐全。日常检索、视觉、真实预约余票、生产容量、完整云环境及高可用不在本轮验收范围。

本机保留两套原有数据与配置恢复点，自动备份继续停用；本轮不删除持久数据或恢复镜像。MIT、第三方许可、贡献及安全报告方式沿用现有文件，本轮未引入第三方代码或素材。未附预构建二进制、未发布 Packages、未部署生产环境。
