# 固定验收批次预算交接

本次固定 ID 为 `optimization-20261026-v1`。此交接没有启用真实采样，也没有发送外部付费请求。预算不足或完整环境未就绪时，允许最终保留零个真实样本，不以合成测试替代真实效果证据。

## 配置边界

仅业务服务的 `FINAL_RUN_ID` 选择批次。客户端 `run_id` 与服务端不一致时拒绝。持久化单例绑定阻止更换服务端编号重新获得额度。已有相同批次的历史计数会被导入而非清空；历史模型调用没有 token 证据时，按 token 额度已耗尽处理。

业务服务上限为文本模型 12、embedding 40、地图 REST 120、保守 token 预留 800000。配置只能进一步收紧，不能突破这些硬上限。原有更严格的任务与日账本仍保留，所有检查在同一数据库事务中完成；并发、重复预留或任一额度检查失败都不会留下部分增量。

Agent 必须启用 `OUTBOUND_LEDGER_REQUIRED=true`，并使用同批次的 `FINAL_RUN_ID` 与 `AMAP_TRANSPORT=rest`。MCP 工具内部可能包含不止一次 REST 请求，不能拿工具调用数证明 REST 次数；固定批次下明确拒绝。普通日常 MCP 使用路径没有被切换。

浏览器高德 SDK 请求不在上述服务器 REST 计数中，必须另行披露。缓存命中没有新发送时不占新请求次数。

## 样本与开发/留出分组

通过业务服务 `FINAL_CAMPAIGN_SAMPLES_JSON` 注册至多四项元数据，每项包括 `sample_id`、根任务规范化 `fingerprint`、`phase`。开发 `development` 与最终留出 `acceptance` 各至多两项。已注册指纹、样本编号与分组不能修改。

`FINAL_RUN_PHASE` 为服务端当前阶段，必须与样本注册分组匹配。调用方不能在请求体中选择阶段。未注册的新输入、同样本不同任务 root、或另一阶段样本都会被拒绝。显式恢复沿任务祖先复用 root 槽位，不获得新配额。

所有任务的第一次实际发送前会自动保留流程槽位；内部工作流预留 API 也只能从有效 execution 派生 root 和指纹。该 API 不接受客户端样本标签来绕过注册。普通无任务攻略和索引请求仍受同一全局调用/token 预算限制。

## token 与账单的区别

模型发送前，以实际序列化请求的 UTF-8 字节数、4096 额外开销和明确的最大输出数保守预留；embedding 按实际批次输入字节与开销预留。模型与视觉客户端提供明确输出上限。固定批次无法界定输出时，发送前停止。失败、取消后不确定响应与崩溃前预留均不退款。

预留是本地保护策略，不是供应商账单或币种费用保证。实际 usage 与供应商计费仍需分别核对。正常非验收 legacy 请求可以继续原有日调用计数路径，不伪称已有 token 上界。
